# Health Bridge AI

A healthcare resource-management dashboard built for a hackathon, with realistic synthetic data for five health centres in India.

## The problem

Health centres can face medicine shortages while others hold surplus stock. Fragmented information about patient demand, beds, and doctor availability makes coordinating resources difficult. Health Bridge AI brings these indicators together and suggests medicine transfers between centres.

## Features

- **Medicine inventory:** Stock, minimum levels, and OK, low, or critical status by centre.
- **Low-stock alerts:** Stock below minimum triggers an alert; below half minimum is critical. Restock sets stock to twice minimum.
- **Redistribution suggestions:** A deterministic algorithm proposes transfers from stock above a donor's 1.5-times-minimum reserve to centres below minimum, aiming for that same reserve level. High-urgency suggestions appear first. Approval updates both centres' stock.
- **Patient statistics:** Today's totals, OPD/IPD/emergency counts, and a seven-day trend.
- **Bed availability:** Occupied and available beds, including ICU availability.
- **Doctor attendance:** Toggle individual doctors present or absent, updating centre and overall totals.
- **Centre filtering:** View all centres or focus on one.
- **English and Hindi:** Switch dashboard labels and translated centre/medicine names.

The demo covers PHC Sitapur, CHC Barabanki, PHC Nalanda, District Hospital Nashik, and CHC Udaipur.

## Demo limitations

All names, stock levels, and healthcare figures are synthetic, not live clinical data. Suggestions are rule-based, not generated by an AI model. Changes exist only in the current page session; refreshing resets the demo. Some doctor totals represent more staff than the displayed sample doctor lists. This is a hackathon demonstration, not a production clinical system.

## Run locally

Install a current Node.js LTS release and npm, then run from the project folder:

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. The demo requires no account, API key, or connected database.

## Run automated tests

Run the complete suite once:

```sh
npm test
```

Keep tests running while developing:

```sh
npm run test:watch
```

Run only the main-feature tests:

```sh
npm test -- src/lib/data.test.ts src/test/dashboard-features.test.tsx
```

Tests use Vitest, React Testing Library, and jsdom:

- `src/lib/data.test.ts`: Redistribution thresholds, donor reserves, quantities, urgency ordering, shared-surplus limits, empty inputs, input immutability, and the demo's first suggestion.
- `src/test/dashboard-features.test.tsx`: Low-stock and critical boundaries, filtering, restocking, approval stock changes, and attendance toggles and totals. Tests exercise the existing dashboard with isolated synthetic fixtures; charts are stubbed because jsdom cannot measure their containers.
- `src/test/app-routing.test.tsx`: The home URL resolves to a page.

These tests validate existing behavior without changing dashboard features or styling. They do not replace live-browser, accessibility, or clinical validation.
